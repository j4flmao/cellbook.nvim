# Contract: Lua ↔ Python Bridge Protocol (v1)

**Transport**: the bridge is started as `<python> -u <plugin>/python/cellbook_bridge.py --protocol 1`. Communication is newline-delimited JSON (one UTF-8 JSON object per line) on stdin (Lua → bridge) and stdout (bridge → Lua). stderr is free-form logs, captured into `:Cellbook log`.

**Lifetime**: one bridge process = one kernel. The bridge exits when stdin closes (Neovim exit), after shutting down its kernel.

## Message envelope

Lua → bridge (request):

```json
{"id": 12, "method": "execute", "params": {...}}
```

Bridge → Lua (response to a request):

```json
{"id": 12, "result": {...}}
{"id": 12, "error": {"code": "kernel_dead", "message": "..."}}
```

Bridge → Lua (event, no id):

```json
{"event": "iopub", "params": {...}}
```

`id` is a positive integer unique per bridge connection, generated by Lua.

## Handshake

1. Bridge starts and immediately emits:
   ```json
   {"event": "hello", "params": {"protocol": 1, "bridge_version": "0.1.0", "python": "/path/to/python", "jupyter_client": "8.6.3"}}
   ```
2. If `jupyter_client` is missing, bridge emits instead and exits with code 3:
   ```json
   {"event": "fatal", "params": {"code": "missing_dependency", "message": "No module named 'jupyter_client'", "fix": "python3 -m pip install jupyter_client ipykernel"}}
   ```
3. Lua rejects protocol mismatch with an actionable error ("update the plugin" / "bridge too old").

## Methods

### `list_kernelspecs`
- params: `{}`
- result: `{"specs": [{"name": "python3", "display_name": "Python 3 (ipykernel)", "language": "python", "argv": [...], "resource_dir": "..."}]}`

### `start_kernel`
- params: `{"kernel_name": "python3", "cwd": "/abs/notebook/dir", "env": {"KEY": "VALUE"}?}`
- result: `{"kernel_id": "uuid", "language_info": {...}}` (after `kernel_info_reply`)
- errors: `no_such_kernel`, `start_failed` (message includes kernel stderr tail)
- Emits `status` events during startup.

### `execute`
- params: `{"code": "print(1)", "cell_id": "abc123", "silent": false, "store_history": true, "stop_on_error": true}`
- result (on `execute_reply`): `{"msg_id": "...", "status": "ok"|"error"|"aborted", "execution_count": 7}`
- The response arrives **after** all iopub output for that request; iopub events carry `cell_id` for routing.
- Requests are sent to the kernel immediately; ordering is guaranteed by the kernel's shell channel. Lua owns the queue and only sends the next `execute` after the previous reply (keeps cancel simple).

### `interrupt`
- params: `{}` → result: `{}` (uses `KernelManager.interrupt_kernel()`; works for signal and message interrupt modes)

### `restart`
- params: `{"clear_namespace": true}` → result: `{"language_info": {...}}`

### `shutdown`
- params: `{}` → result: `{}`; bridge then exits with code 0.

### `complete` *(post-MVP, spec 002)*
- params: `{"code": "...", "cursor_pos": 42}` → result: `complete_reply.content`

### `inspect` *(post-MVP, spec 002)*
- params: `{"code": "...", "cursor_pos": 42, "detail_level": 0}` → result: `inspect_reply.content`

### `ping`
- params: `{}` → result: `{"alive": true, "kernel_state": "idle"}`

## Events

### `status`
`{"event": "status", "params": {"state": "starting"|"idle"|"busy"|"restarting"|"dead"}}`

### `iopub`
Forwarded iopub messages relevant to output, routed by the `cell_id` of the originating request (`parent_header.msg_id` → `cell_id` map kept in the bridge):

```json
{"event": "iopub", "params": {
  "cell_id": "abc123",
  "msg_type": "stream"|"execute_result"|"display_data"|"update_display_data"|"error"|"clear_output"|"execute_input",
  "content": { ... Jupyter message content, unchanged ... },
  "metadata": { ... }
}}
```

- `update_display_data` events may have `cell_id: null` if the display originated from another request; Lua routes by `content.transient.display_id`.
- Binary-heavy MIME data (images) is passed inline as base64 strings exactly as Jupyter sends them; Lua writes them to the image cache.

### `log`
`{"event": "log", "params": {"level": "debug"|"info"|"warn"|"error", "message": "..."}}`

### `fatal`
Unrecoverable bridge error; bridge exits afterwards. Lua marks the session `dead`.

## Error codes

| code | meaning | Lua behavior |
|---|---|---|
| `missing_dependency` | jupyter_client / kernel package missing | notify with `fix`, point to checkhealth |
| `no_such_kernel` | kernelspec not found | prompt kernel selection |
| `start_failed` | kernel process failed to start | show stderr tail |
| `kernel_dead` | kernel died (heartbeat failure) | session → dead, offer restart |
| `busy` | method not allowed in current state | retry or ignore |
| `invalid_request` | malformed request | bug: log + notify in debug |
| `internal` | unexpected exception | log traceback, notify |

## Non-functional requirements

- Bridge must flush stdout after every line (`print(..., flush=True)` or `-u`).
- Bridge must not print anything except protocol lines to stdout.
- Throughput: ≥ 5,000 iopub events/s without dropping; Lua side coalesces renders.
- Python compatibility: 3.9–3.13; dependencies limited to stdlib + `jupyter_client`.
- Versioning: any breaking change bumps `protocol`; plugin and bridge ship together so mismatches only occur with stale caches.
